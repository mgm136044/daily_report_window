## 한눈에

| 준비물 | 필수 | 비고 |
|---|---|---|
| macOS | ✅ | `launchd`·`caffeinate` 를 쓴다. 리눅스·윈도우는 지원하지 않는다 |
| Python 3.11 이상 | ✅ | `tomllib` 때문. **외부 패키지는 하나도 필요 없다** |
| Claude Code CLI (로그인 상태) | ✅ | 보고서를 쓰는 주체. 구독 계정이면 추가 과금 없다 |
| git | ✅ | macOS 기본 탑재 |
| 노션 계정 + 워크스페이스 | ✅ | 그 워크스페이스의 **소유자**여야 연결을 만들 수 있다 |
| 노션 내부 연결 토큰 | ✅ | 아래 절차 |
| 부모 페이지 1개 | ✅ | 보고서 데이터베이스가 들어갈 자리 |
| 본인 git 이메일 목록 | ✅ | 없으면 커밋이 하나도 집계되지 않는다 |
| Codex CLI | — | 있으면 자동으로 함께 수집한다. 없으면 조용히 건너뛴다 |

버전 확인:

```bash
sw_vers -productVersion      # macOS
python3 --version            # 3.11 이상
claude --version             # 설치 확인
claude auth status           # 로그인 확인 (여기서 막히면 claude 로 로그인)
```

## 노션 토큰 발급

### 왜 "내부 연결" 인가

노션에는 토큰이 세 종류 있고, 자동화에 쓸 수 있는 건 하나뿐이다.

| 종류 | 만료 | 접근 범위 | 판단 |
|---|---|---|---|
| **내부 연결 (Internal connection)** | **없음** | 명시적으로 공유한 페이지만 | ✅ **이걸 쓴다** |
| 개인 액세스 토큰 (PAT) | 7일~1년 | 만든 사람이 볼 수 있는 **전부** | ❌ 만료되면 어느 날 조용히 멈춘다 |
| 공개 연결 (OAuth) | 갱신 필요 | 승인 범위 | ❌ 브라우저 승인이 필요해 무인 실행에 부적합 |

내부 연결은 사람이 아니라 **봇 사용자**로 동작한다. 만든 사람이 워크스페이스를 떠나도 접근이 유지되고, 공유한 페이지 밖으로는 아무것도 못 본다.

### 절차

**순서가 중요하다.** 연결이 먼저 있어야 페이지에 붙일 수 있다.

```
① 연결 만들기 (토큰이 여기서 나온다)
        ↓
② 부모 페이지 만들기
        ↓
③ 페이지에 연결 붙이기
```

#### ① 연결 만들기

1. 보고서를 넣을 워크스페이스로 노션에 로그인한다.
2. `app.notion.com/developers/connections` 로 간다.
3. 왼쪽 **Build → Internal connections**
4. **Create a new connection** — 이름을 정하고(예: `daily-report`) **워크스페이스를 정확히 선택**한다.
5. **Configuration** 탭에서 **Installation access token** 을 복사한다.
   연결 목록에서 `•••` → *Retrieve an internal API token* 으로도 얻을 수 있다.

> 이 메뉴가 보이지 않으면 그 계정에 연결 생성 권한이 없을 수 있다.
> 공식 문서는 워크스페이스 소유자를 요구한다고 기술한다.

토큰은 `ntn_` 또는 `secret_` 으로 시작하는 긴 문자열이다.

#### ② 부모 페이지 만들기

워크스페이스 안에 빈 페이지를 하나 만든다. 이름은 아무거나(예: "개발 일지").

**전용 페이지를 따로 파는 이유**: 접근 권한은 하위 페이지로 상속된다. 기존에 쓰던 큰 페이지에 붙이면 그 아래 전부가 연결에 노출된다. 새 페이지를 만들면 노출 범위가 그 아래로만 갇힌다.

#### ③ 페이지에 연결 붙이기

1. 그 페이지를 연다.
2. 오른쪽 위 **`•••`**
3. 팝업 **맨 아래** **Add connections**
4. ①에서 만든 연결을 검색해 선택
5. 하위 페이지까지 접근한다는 확인이 뜨면 승인

`•••` 메뉴에 연결 이름이 보이면 성공이다.

> **`Share` 버튼이 아니다.** 사람을 초대하는 `Share` 와 연결을 붙이는 `Add connections` 는
> 다른 메뉴다. 예전 노션은 공유 대화상자 안에 있었지만 지금은 `•••` 로 빠졌다.

안 보이면 개발자 포털에서도 할 수 있다: 연결 열기 → **Content access** 탭 → **Edit access** → 페이지 선택.

#### ④ 페이지 URL 복사

페이지에서 링크를 복사한다. `https://app.notion.com/…` 형태이고, `setup_notion_db.py` 가 여기서 페이지 ID 를 뽑는다.

## 넘겨야 할 값

둘뿐이다. 둘 다 `.env` 에 넣는다.

| 값 | 예 |
|---|---|
| 토큰 | `ntn_…` (50자 안팎) |
| 부모 페이지 URL | `https://app.notion.com/p/…` |

데이터베이스는 **스크립트가 만든다.** 손으로 만들지 않는 이유는, 속성이 11개인데 이름이 한 글자만 달라도 날짜 조회가 빗나가 **매일 새 행이 쌓이기** 때문이다. 그리고 그 사실을 며칠 뒤에나 알아차리게 된다.

> **토큰을 채팅·이슈·스크린샷에 붙여넣지 말 것.** 파일(`.env`, 권한 600)에만 둔다.

## 안 될 때

| 증상 | 원인 | 조치 |
|---|---|---|
| `404 object_not_found` | 부모 페이지에 연결이 공유되지 않음 | ③번 단계 다시 |
| 읽기는 되는데 쓰기만 `403` | insert content 권한 없음 | Configuration 에서 권한 켜기 |
| `401 unauthorized` | 토큰이 잘못됐거나 만료 | 토큰 재확인. PAT 을 쓰고 있다면 내부 연결로 바꾼다 |
| 연결 생성 메뉴가 안 보임 | 계정 권한 | 워크스페이스 소유자 계정으로 시도 |
| Enterprise 요금제에서 설치 차단 | 소유자가 설치 가능 연결을 제한 | 소유자에게 허용 요청 |

설치 후 언제든 상태를 확인할 수 있다:

```bash
python3 doctor.py --full
```

검사 순서가 인과 순서(스케줄러 → 설정 → 인증 → 노션)라서, **위에서부터 읽으면 첫 실패가 대개 원인**이다.

## 그 밖에 정할 것

설치 후 `config.toml` 에서 조정한다. 전부 나중에 바꿔도 된다.

| 항목 | 왜 중요한가 |
|---|---|
| `[git] authors` | **본인 이메일 전부.** 비우면 커밋이 하나도 집계되지 않는다. 홈 디렉터리에 남의 저장소 포크가 있으면 이 목록이 남의 작업을 걸러내는 유일한 장치다 |
| `[exclude] paths` | 애초에 수집하지 않을 폴더. 클라이언트 업무처럼 노션에 올리면 안 되는 영역을 여기 넣는다 |
| `[report] language` | `ko` 또는 `en` |
| `[day] boundary_hour` | 하루의 경계. 기본 4시 — 새벽 2시 작업이 전날로 잡힌다 |

본인 이메일을 찾는 법:

```bash
git config user.email
git log --format='%ae' | sort | uniq -c | sort -rn | head
```
